**Elevator Pitch**
หยิบลูกแก้วจากหลุมฝั่งตัวเองไปหยอดรอบกระดาน ถ้าเม็ดสุดท้ายตกหลุมที่มีเม็ดอยู่ก็หยิบหว่านต่อเป็นทอด ๆ จนไปตกหลุมว่างฝั่งตัวเอง แล้วกินหลุมตรงข้ามของคู่แข่งเข้าเรือน
ความสนุกอยู่ที่การคิดว่าหว่านต่อครั้งเดียวจะไปจบที่ไหน และลุ้นทีละเม็ดที่หยอดลงไป ทั้งหมดอยู่ในงานพิกเซลอาร์ตกลิ่นอายไทยที่เล่นได้ทั้งบนคอมและมือถือ

**Unique Selling Points**
1. **กติกาหมากขุมแบบไทยจริง:** มีการหว่านต่อ การกินหลุมตรงข้าม การได้เดินอีกตา และเกมหลายรอบที่มี "หลุมตาย" ไม่ใช่ Kalah ที่เปลี่ยนชื่อ
2. **พิกเซลอาร์ตกลิ่นอายไทย:** กระดานไม้ทรงเรือ เม็ดลูกแก้ว ลวดลายไทย และเสียงจากเครื่องดนตรีไทย
3. **เล่นได้ 2 แบบ:** 2 คนบนเครื่องเดียว หรือเล่นกับ AI 3 ระดับ
4. **เปิดเล่นได้ทันที:** เป็นเว็บเกม เล่นบนมือถือแนวนอนได้ และติดตั้งเป็นแอป (PWA) ได้
5. **โหมดสอนเล่นแบบลงมือทำ:** มือใหม่เรียนกติกาครบใน 3 นาที <!-- ASSUMPTION -->

## Section 2 — Core Game Loop

### 30-Second Loop (1 ตา)

```
[Pick own pit] --> [Sow 1 seed per pit, CCW] --> [Where does the LAST seed land?]
      ^                                                   |
      |        +------------------------------------------+-----------------------------+
      |        |                 |                        |                             |
      |   non-empty pit     own empty pit            opponent's empty pit           own store
      |        |                 |                        |                             |
      |     RELAY:          CAPTURE opposite         turn ends                   EXTRA TURN
      |   pick up all,      pit + last seed               |                             |
      |   keep sowing       -> own store,                 |                             |
      |        |            turn ends                     |                             |
      |        +--> (back to "last seed")                 |                             |
      |                          |                        |                             |
      +------ opponent's turn <--+------------------------+          same player <------+
```

ความหมาย: Pick own pit = เลือกหลุมฝั่งตัวเอง, Sow CCW = หว่านทวนเข็มนาฬิกา, RELAY = หว่านต่อ, CAPTURE = กิน, EXTRA TURN = ได้เดินอีกตา

### 5-Minute Loop (1 รอบ หรือ "เกมสั้น")

```
[Setup 7 seeds x 14 pits] --> [Turns alternate] --> [A player has no seeds? -> PASS]
                                     ^                         |
                                     +-------------------------+
                                                               |
                                            all 14 pits empty -> [ROUND END: compare stores]
```

### Session Loop

```
Short game:  [Menu] -> [1 round] -> [Result] -> [Rematch?] --yes--> [1 round] ...
                                                     |
                                                     no --> [Menu]

Full game:   [Menu: pick 3/5/7 rounds] -> [Round 1] -> [Round end]
                                             ^              |
                                             |    someone has < 7 seeds? --yes--> [GAME OVER: they lose (R15)]
                                             |              | no
                                             |    was it the last round? --yes--> [GAME OVER: more seeds wins (R16)]
                                             |              | no
                                             +-- [Refill pits; unfillable pits become DEAD]
```

- **เกมสั้น:** 1 รอบ ใช้เวลาประมาณ 3–5 นาที (วัดแล้ว ดู Appendix A ข้อ 3)
- **เกมเต็ม:** 3, 5 หรือ 7 รอบ (R16) แบบ 3 รอบใช้เวลาประมาณ 7–15 นาที (วัดแล้ว) บันทึกทุกตาและกลับมาเล่นต่อได้

### Win / Lose Conditions

| โหมด | ชนะ | แพ้ | เสมอ |
|---|---|---|---|
| เกมสั้น (1 รอบ) | จบรอบแล้วมีเม็ดในเรือนมากกว่า | มีเม็ดในเรือนน้อยกว่า | 49 : 49 |
| เกมเต็ม (3/5/7 รอบ) | คู่แข่งเหลือเม็ดในเรือนไม่ถึง 7 ตอนจบรอบไหนก็ได้ (R15) หรือ จบรอบสุดท้ายแล้วมีเม็ดในเรือนมากกว่า (R16) | กรณีกลับกัน | 49 : 49 ตอนจบรอบสุดท้าย |

หลังจบเกมมีปุ่ม "เล่นอีกครั้ง" และ "กลับเมนู" ระหว่างเกมมีปุ่ม "ยอมแพ้" ให้กดได้ <!-- ASSUMPTION -->

### 3.2 โมเดลกระดานและการนับเลขหลุม

ใช้อาร์เรย์ `pits[16]` ช่องเดียว ทั้ง rules engine และ AI ใช้ร่วมกัน

```
                 P2 (sits at top, faces down)
         [14] [13] [12] [11] [10]  [9]  [8]     <- P2 pits (P2's left = screen right)
  [15]                                         [7]
 P2 store                                    P1 store
         [0]  [1]  [2]  [3]  [4]  [5]  [6]      <- P1 pits
                 P1 (sits at bottom)

 P1 sows: 0 -> 1 -> ... -> 6 -> 7 -> 8 -> ... -> 14 -> (skip 15) -> 0
 P2 sows: 8 -> ... -> 14 -> 15 -> 0 -> ... -> 6 -> (skip 7) -> 8
 Both are counter-clockwise on screen.  opposite(i) = 14 - i
 Refill order (nearest own store first): P1: 6,5,4,3,2,1,0   P2: 14,13,...,8
```

- `pits[0..6]` คือหลุมของ P1 และ `pits[7]` คือเรือนของ P1 อยู่ขวาจอ ตรงกับขวามือของ P1
- `pits[8..14]` คือหลุมของ P2 และ `pits[15]` คือเรือนของ P2 อยู่ซ้ายจอ ตรงกับขวามือของ P2 ที่นั่งหันหน้าเข้าหา P1
- `dead: Set<pitIndex>` เก็บหลุมตาย ใช้เฉพาะเกมเต็ม
- เงื่อนไขที่ต้องจริงเสมอ: `sum(pits) == 98` ในทุกจังหวะของเกม

### 3.3 อัลกอริทึม 1 ตา (pseudocode)

```
playTurn(state, player, startPit):
  require startPit in ownPits(player), startPit not dead, pits[startPit] > 0
  hand = pits[startPit]; pits[startPit] = 0; pos = startPit          -> event PICKUP
  loop:
    while hand > 0:
      pos = next(pos, player)     # +1 mod 16, skip opponent's store, skip dead pits
      pits[pos] += 1; hand -= 1                                       -> event DROP
    if pos == ownStore(player):                 return EXTRA_TURN     # R8
    if pits[pos] > 1:                                                 # pit was non-empty
      hand = pits[pos]; pits[pos] = 0                                 -> event RELAY  # R5
      continue loop
    # pits[pos] == 1  -> pit was empty before the last seed
    if pos in ownPits(player) and pits[opposite(pos)] > 0:            # R6
      store(player) += pits[opposite(pos)] + 1
      pits[opposite(pos)] = 0; pits[pos] = 0                          -> event CAPTURE
    return TURN_END                                                   # R6 (no capture) / R7

afterTurn(result):
  candidate = (result == EXTRA_TURN) ? player : other(player)
  if hasSeeds(candidate):          next = candidate
  elif hasSeeds(other(candidate)): next = other(candidate)             -> event PASS  # R9
  else:                            ROUND_END                                          # R10
```

Rules engine อยู่ที่ `src/logic/` เขียนเป็น TypeScript ล้วนที่ไม่ขึ้นกับ Phaser engine คืนค่าเป็นรายการ step (`pickup`, `drop` ทีละเม็ด, `relay`, `capture`, `extraTurn`, `turnEnd`, `pass`, `roundEnd`, `gameOver`, `refill`, `deadPit`, `roundStart`) ให้ scene เอาไปเล่น animation ตามลำดับ วิธีนี้ทำให้ทดสอบกติกาด้วย unit test ได้โดยไม่ต้องเปิดเกม

### 3.4 จบรอบและเกมหลายรอบ (เกมเต็ม)

```
ROUND_END
  -> winner of round = player with more seeds in store (tie: none)
  -> Short game: show result. Done.
  -> Full game:
       if a player has < 7 seeds (cannot fill 0 pits)  -> GAME_OVER, that player loses (R15)
       else if this was round maxRounds (3/5/7)        -> GAME_OVER, more seeds wins, 49:49 draw (R16)
       else:
         for each player: fill own pits with 7 seeds each, starting nearest own store (R13)
                          pits that cannot be filled -> DEAD for this round
                          leftover (<7) stays in store (A3)
         next round; starter = loser of previous round (R14) / tie: A5
```

ตัวอย่าง: จบรอบด้วย P1 = 51 และ P2 = 47
- P1 เติมครบ 7 หลุม ใช้ไป 49 เหลือ 2 ในเรือน
- P2 เติมได้ 6 หลุม (14 ถึง 9) ใช้ไป 42 เหลือ 5 ในเรือน หลุม 8 เป็นหลุมตาย
- P2 เป็นคนเริ่มรอบถัดไป

### 3.5 Edge Cases

| กรณี | ผลลัพธ์ |

### 3.6 การรับประกันว่าเกมต้องจบ

- **ภายใน 1 ตา:** ถ้าหว่านต่อไม่สิ้นสุด แปลว่าต้องวนผ่านเรือนตัวเองไม่สิ้นสุด แต่ทุกครั้งที่ผ่านจะมีเม็ด 1 เม็ดออกจากหลุมเข้าเรือน และเม็ดมีจำกัด ดังนั้นหนึ่งตาต้องจบเสมอ
- **ภายใน 1 รอบ:** ตาที่เรือนไม่เพิ่มเลย คือตาที่เม็ดเคลื่อนเฉพาะในแถวของผู้เดินและไปทางเรือนของตัวเอง เพราะถ้าจะออกจากแถวตัวเองต้องผ่านเรือนตัวเองก่อน ดังนั้นตาแบบนี้ต่อกันได้จำนวนจำกัด และเม็ดในเรือนรวมกันไม่เกิน 98 รอบจึงต้องจบเสมอ
- **Implementation guard:** ถึงจะพิสูจน์ได้ ก็ยังใส่ assert ไว้ ถ้าหนึ่งตาหยอดเกิน 5,000 ครั้ง หรือหนึ่งรอบเกิน 2,000 ตา ให้ throw error ใน dev build เพื่อจับ bug

## Section 4 — Progression System

เป็นเกมกระดานดั้งเดิม ความก้าวหน้าจึงมาจาก**ฝีมือของผู้เล่น** ไม่มีระบบอัปเกรดหรือ power-up ที่ทำให้กติกาเพี้ยน

- **Difficulty Curve:** ผู้เล่นเลือกเองแบบขั้นบันได คือ Tutorial → AI ง่าย → AI กลาง → AI ยาก แล้วค่อยลองเกมเต็มกับ AI ยาก
- **Unlock Sequence:** v1 ไม่ล็อกอะไรเลย <!-- ASSUMPTION --> หลัง v1 อาจให้ลายกระดานหรือสีเม็ดเป็นรางวัลเมื่อชนะ AI ยาก (cosmetic เท่านั้น) <!-- ASSUMPTION -->
- **Scoring System:** คะแนนคือจำนวนเม็ดในเรือน ไม่มีตัวคูณ ส่วนหน้าสถิติเก็บข้อมูลต่อไปนี้ <!-- ASSUMPTION -->
  - ชนะ แพ้ เสมอ แยกตามโหมดและระดับ AI
  - กินได้มากที่สุดในครั้งเดียว
  - หว่านต่อยาวที่สุด (นับเป็นจำนวนทอด)
  - ชนะห่างมากที่สุด
  - **ทำแล้ว (2026-11-24):** `src/stats.ts` และหน้า "สถิติ" นับผลแยกตามคู่แข่งและเกมสั้นหรือเกมเต็ม (รวม 2 กติกาไว้ด้วยกัน) เมื่อเล่นกับ AI ผู้เล่น 1 คือคน ส่วนโหมด 2 คนนับว่าใครชนะ สถิติพิเศษนับเฉพาะการเดินของคน ยอมแพ้นับเป็นแพ้แต่ไม่นับในสถิติ "ชนะห่าง" มีปุ่มล้างสถิติที่ต้องกด 2 ครั้ง หน้าผลแพ้ชนะแสดง "กินมากสุดในครั้งเดียว" และ "หว่านต่อยาวสุด" ของเกมนั้น ซึ่งบันทึกไปกับเกมที่เล่นค้างด้วย
- **Replayability Hooks:** AI 3 ระดับ เกมเต็มที่พลิกเกมได้ด้วยหลุมตาย สถิติ และการชวนเพื่อนเล่นบนเครื่องเดียว หลัง v1 อาจมี "โจทย์หมากขุม" แบบ puzzle รายวัน <!-- ASSUMPTION -->
- **Estimated Play Time:** เรียนกติกา 3 นาที <!-- ASSUMPTION --> ที่เหลือวัดแล้วเมื่อ 2026-11-24 (Appendix A ข้อ 3) ได้แก่ เกมสั้น 3–5 นาที เกมเต็ม 3 รอบ 7–15 นาที 5 รอบ 12–25 นาที และ 7 รอบ 15–34 นาที

### Integer Scaling (คำนวณจาก device pixel)

```
k    = max(1, floor(min(viewportW * dpr / 480, viewportH * dpr / 270)))
zoom = k / dpr          # Phaser scale.mode = NONE, autoCenter = CENTER_BOTH, setZoom(zoom)
# canvas backing stays 480x270; each game pixel = exactly k x k device pixels -> crisp
# recompute on resize / orientationchange
```

| อุปกรณ์ (ตัวอย่าง) | Viewport (CSS) | dpr | k | ขนาดเกมบนจอ (CSS) |
|---|---|---|---|---|
| Desktop FHD ในเบราว์เซอร์ | ≈1920×969 | 1 | 3 | 1440×810 |
| Desktop FHD เต็มจอ | 1920×1080 | 1 | 4 | 1920×1080 |
| Laptop 1366×768 | ≈1366×657 | 1 | 2 | 960×540 |
| Android 915×412 เต็มจอ | 915×412 | 2.625 | 4 | ≈731×411 |

**ข้อสังเกต:** iPhone ใช้ Fullscreen API ไม่ได้ ถ้าเปิดใน Safari ตรง ๆ จะเหลือขอบเยอะ จึงควรแนะนำให้ "เพิ่มไปยังหน้าจอโฮม" (PWA) ส่วน Android ขอเต็มจอได้ตอนแตะครั้งแรก

### ความเสี่ยงทางเทคนิค: ตัวอักษรไทยบนพิกเซล 480×270

- ตัวเลขใช้ bitmap font 5×7 ที่ทำเอง ได้ภาพคมแน่นอน

  - **ทุกข้อความในเกม**ใช้ `PixelText` (`src/display/pixelText.ts`) ทำงานแบบนี้:
    1. วาดด้วย canvas ของเบราว์เซอร์ จึงจัดสระและวรรณยุกต์ได้ถูก

    - ป้ายภาษาอังกฤษหรือตัวเลขสั้น ๆ เช่น "P1" เล็กกว่านี้ได้
    - ข้อความบนพื้นไม้ใส่ขอบมืด 1 พิกเซล
  - เครดิตฟอนต์อยู่ในหน้าเครดิต และไฟล์ license อยู่ที่ `public/licenses/Mali-OFL.txt`

## Appendix D — Roadmap ออนไลน์ และการเตรียมพร้อม

**ตัดสินแล้ว (2026-11-23):**

| เวอร์ชัน | ขอบเขต | สถานะ |
|---|---|---|
| **v1** | **ออฟไลน์อย่างเดียว**: 2 คนเครื่องเดียว, AI 3 ระดับ, จอย | ทำก่อน และต้องเสร็จก่อนเริ่มงานออนไลน์ |
| **v2** | **ออนไลน์ระดับ (ก)**: ห้องเล่นด้วยรหัสเชิญ ไม่ต้องมีบัญชี | เริ่มหลัง v1 launch |
| ภายหลัง | ระดับ (ข) บัญชีและประวัติ, ระดับ (ค) จับคู่และอันดับ | เก็บไว้ก่อน ยังไม่กำหนดเวลา |

ห้ามเพิ่ม backend, ระบบบัญชี หรือฐานข้อมูลเข้ามาใน v1 สิ่งที่ v1 ทำได้มีแค่การเตรียมโครงตาม 5 ข้อด้านล่าง ซึ่งไม่ทำให้งานเพิ่ม

v1 เล่นออฟไลน์อย่างเดียว แต่ออกแบบไว้ให้เพิ่มโหมดออนไลน์ได้โดยไม่ต้องรื้อของเดิม

1. **ใช้ rules engine ตัวเดียวกันบน server:** engine เป็น TypeScript ล้วนและ deterministic server จึงตรวจทุกการเดินได้เอง (server-authoritative) ผู้เล่นโกงด้วยการแก้ client ไม่ได้
2. **เก็บเกมเป็น move log:** การเดิน 1 ครั้งคือข้อมูลขนาดเล็ก `{ pit }` จึงเก็บเกมเป็นรายการการเดินแล้ว replay ได้เสมอ ไม่ต้องเก็บกระดานทุกตา
3. **เพิ่ม `RemoteController` ได้ทันที:** Turn controller เป็น interface อยู่แล้ว (§10) เพิ่มได้โดยไม่ต้องแก้ Game scene
4. **server เป็นคนสุ่ม:** ในโหมดออนไลน์ การสุ่มคนเริ่มต้องย้ายไปทำที่ server
5. **save มี version ตั้งแต่ v1:** ย้ายข้อมูลเข้าฐานข้อมูลได้ทีหลัง

ระดับที่เป็นไปได้มี 3 ระดับ
- (ก) ห้องเล่นด้วยรหัสเชิญ ไม่ต้องมีบัญชี
- (ข) เพิ่มบัญชี ประวัติการเล่น และสถิติบน server
- (ค) เพิ่มจับคู่อัตโนมัติ คะแนน rating และกระดานผู้นำ

ตัวเลือก backend เช่น Supabase (Postgres + Auth + Realtime) หรือ Colyseus + Postgres ให้ตัดสินตอนเริ่ม v2
